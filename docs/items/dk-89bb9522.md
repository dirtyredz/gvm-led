# Release signing: reclaim the publish lock when its PID is dead

When a publish-release.ps1 run is killed mid-signing (2026-11-01, 0.1.6), %TEMP%\dirtyredz-gvm-led-android-publish.lock stays behind with {pid, at}. The next run refuses with 'delete it by hand'. secrets.js should check whether the recorded PID is still alive and reclaim the lock if it isn't; it should still refuse while that process is alive.
